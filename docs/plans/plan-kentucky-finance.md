# Kentucky reported finance components

## Evidence and decision before implementation

The current KREF public searches expose complete candidate-receipt and independent-expenditure CSV exports. Genuine October 18, 2026 research found 48,190 primary and 19,382 general receipt rows, 267 primary and 162 general IE rows. The candidate census includes closed and no-receipt registrations: 4,677 primary and 5,697 general rows, matching native result counts. Repeated receipt exports can reorder equal-date rows; compare complete occurrence multisets, preserving duplicate multiplicities. Negative receipts use parentheses. The old client takes absolute values and the old sync excludes all legislative IE because IE records lack districts.

Use independent `committee` and `ie` components, each with its own saved-first source acquisition, clocks, retry attempts, writer and reader validation. A direct-source failure must not suppress IE acquisition or publication. Keep the legacy receipts, summary, outside groups and all their clocks untouched by this job. The ordinary Kentucky due sync invokes the component job even when no legacy summary is due; a component CLI permits running it alone.

Three source questions are resolved as follows:

1. **What is available?** Complete current public-search ledgers for the regular May 19 primary and November 3 general election. This first implementation supports the verified 2026 regular cycle only. It does not infer future election dates, special elections, report revisions or legal donor IDs.
2. **What is authoritative and complete?** Save genuine raw responses before parsing. For each election and component bracket the full export with native result counts and a repeated full export; also bracket a complete all-status candidate census. Verify strict UTF-8, exact CSV schema/width/quoting, full occurrence multisets and native counts. These are observations of the current public ledger, not a claim that the export supplies report-amendment IDs. Never deduplicate transactions using guessed IDs or use a latest-report rule that KREF does not expose.
3. **What can be attributed?** Require one active canonical candidate/election/link and an unambiguous full source census name/office/district context. IE requires an explicit single target, office, election and stance, and a unique district context in the complete census, including closed registrations. Ambiguous or missing targets are held, not assigned zero. Receipt rows additionally require exact source recipient/context. Typed PAC/party/caucus/campaign-committee and contributing-organization receipts are reported entities, not independently verified legal PACs. Exclude generic Other, individuals, self, anonymous/unitemized, transfers, loans and repayments. Preserve signed corrections within the same full reported class/name/address group; negative net groups hold the component. Separate expenditure returns are outside this receipt-ledger scope. No invented allocations or inferred PAC types from names.

The independent three-table store keeps complete uncapped groups and source/count/money controls. Recheck and lock the canonical receiver before atomic replacement. Older or conflicting equal-clock sources preserve prior money; equal-source replay cannot repair inconsistent stored rows. Reader validates full closure before the five-name display cap. Each component reports its own source date and coverage without refreshing legacy headline dates or campaign totals. Gates default off under the existing Kentucky master.

## Local validation, October 18

The production saved-first producer and second complete original replay qualified 67,572 receipt rows (733 signed negatives), 429 IE rows and 10,374 census records. Complete source packets contain 39,076,209 receipt bytes and 2,800,946 IE bytes, observed at 07:18 UTC. A read-only replay across all 165 eligible receivers qualified 163 contexts; two remained held. This is source qualification, not a claim that every receiver has been synced.

The ordinary default-25 independent component batch attempted 50 components and wrote 48: 24 committee and 24 IE components. One receiver remained held in both components. Accepted totals: $592,932.90 committee receipts and $84,124.66 IE support, across 430 uncapped stored groups. Twenty-two accepted IE observations were verified empty and two positive. Complete stored names, classes, addresses/keys, amounts, counts, receiver contexts, source controls and clocks matched original replay in memory. All five legacy Kentucky tables, every row/clock and the migration ledger remained unchanged during sync. Local migration 358 is applied; older local migrations were not modified.

A final retry regression ensures canonical context edits are due immediately even when stored money is fresh. A second ordinary default-25 batch on that code wrote 50 additional components, preserving every prior component/group. Combined acceptance is 98 components across 843 groups: $1,098,941.73 committee receipts, $136,419.79 IE support and $127,567.92 IE opposition. Of 49 accepted contexts, 46 have positive committee receipts and three verified-empty; six have positive IE and 43 verified-empty. These two batches attempt 50 receivers, not all 165. All legacy rows/clocks and the ledger remained unchanged again. Focused validation comprises 157 Kentucky/finance-isolation tests plus the full backend typecheck.

The actual production API and hydrated candidate page verified $88,350 across 36 reported committee groups and $83,001.43 IE support across two outside groups. Five committee names are displayed only after complete closure. Existing raised money and July 21 headline date stayed unchanged; both component coverage notes show October 18. Named panels were closed after inspection; no screenshots or identity-bearing private proofs were saved. The preview initially targeted the default local API port; the network guard blocked it, and an explicit loopback SSR API configuration fixed the preview without widening access.

Deployment gates remain default-off: `KENTUCKY_REPORTED_COMMITTEE_ENABLED`, `KENTUCKY_REPORTED_IE_ENABLED`, and `KENTUCKY_REPORTED_RAW_REFRESH_ENABLED`, each under `KENTUCKY_CAMPAIGN_FINANCE_ENABLED`. `KENTUCKY_REPORTED_CACHE_DIR` optionally selects the private original cache. The existing ordinary due job invokes components independently of legacy staleness. `npm run kentucky-candidates:finance:sync-reported` runs components alone; `--refresh` still requires the raw-refresh gate. The first implementation intentionally holds unsupported cycles and unresolved identities.
