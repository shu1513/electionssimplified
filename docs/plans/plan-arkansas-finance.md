## Historical direct-only plan

Written 2026-08-26 after a live API probe (all endpoints below exercised with curl the same day; six bulk CSVs downloaded and analyzed; one cent-level reconciliation attempted) plus a codebase reuse audit, and after reviewing an external 2026-08-03 feasibility report whose portal-availability findings were wrong (its research environment hit the DNS defect below; the portal was up). Companion findings doc with the full endpoint map: `backend/docs/arkansas-campaign-finance.md`. Verdict: **GO — Phase 0 first.** Direct finance + donor occupations ship; candidate-specific outside spending does NOT (no structured stance/target anywhere in the source — proven, not suspected). No schema and no published numbers until the Phase 0 gates pass.

Arkansas is the **same Civix CFIS build as the shipped New Hampshire module** (`backend/src/pipeline/newHampshireFinance/`, migration 249) — same `{data, succeeded, error}` wrapper, same `ExportData/GetExportPublicDownloadData` bulk export, same Angular SPA. This plan mirrors NH file-for-file and diverges only where the AR deployment differs (endpoint names, thinner transaction-search rows, occupation coverage, no IE stance). Since Acts 524/994 of 2025, county and municipal candidates also file here — the office lookup enumerates 42 offices from Governor down to School Board Member, Constable, and Justice of the Peace, so one module covers state and local candidates (Missouri-style), with the usual caveat that registration-level presence is not proof of complete local filings.

## Verified sources (probed live 2026-08-26)

### Access reality: open API, but a DNS defect on some resolvers

- SPA: https://ethics-disclosures.sos.arkansas.gov (Angular; Azure Front Door, CNAME `arcfis-*.azurefd.net`). Launched Sept 2023.
- API: **https://api-ethics-disclosures.sos.arkansas.gov/api** — anonymous JSON, no auth, no token, no reCAPTCHA on any endpoint used here (the SPA holds a recaptcha site key for filer flows only).
- **DNS defect (verified):** both hostnames return NXDOMAIN from some resolvers (a residential router resolver and Anthropic's fetcher both failed) while 8.8.8.8 and 1.1.1.1 resolve fine. All probes ran with `curl --resolve` pinned to 150.171.109.145 (site) / 150.171.109.146 (api). **Phase 0 gate 1 verifies plain Node `fetch` on the run host's default resolver.** If the run host is affected, fix the host's resolver — do NOT pin Front Door IPs in the client (they rotate). The client should detect ENOTFOUND and fail with a message naming this known defect.
- Endpoint constants live in the SPA's `common.<hash>.js` webpack chunk, not `main.js` — that is where the map below came from.
- Pre-Sept-2023 era: the 2017–2023 predecessor system's host is dead (DNS gone); CFIS carries `PublicLegacyFiledReport/*` endpoints (empty on a bare paging probe — needs a filer-scoped probe if legacy history is ever wanted) and the ark.org archive covers the pre-2017 paper era. Irrelevant for v1: CFIS transaction exports cover filing years **2022–2026** (2022 is a small back-file of late-2022 transactions), which fully contains the Nov-2026 cycle.

### Bulk CSV exports (the NH pattern, verified byte-for-byte)

`POST /api/ExportData/GetExportPublicDownloadData` body `{"type":"CSV","filingYear":<YYYY>,"transactionTypeCode":"TCON"|"TEXP"}` → **synchronous CSV response** (no catalog step, unlike NM). Verified sizes: TCON 2022 = 0.4 MB, 2023 = 69 MB, 2024 = 103 MB, 2025 = 119 MB, 2026 = 92 MB / 304,193 rows / $36.3M; TEXP 2026 = 6 MB / 20,591 rows / $31.5M. Amounts are `"$5,000.00"` strings (parentheses possible), dates MM/DD/YYYY — reuse the NH CSV parser approach (`newHampshireCfsCsv.ts`), never naive splitting.

TCON columns: `Filing Entity ID, Entity Name, FilerType, Transaction Type, Transaction Sub Type, Funding Source / Loan Source Type, Source Name, Source Address, Employer Name, Occupation, Occupation Other, Transaction Date, Transaction Amount, Transaction Description, Transaction ID, Election Type, Election Year, Guarantor Name, Guarantor Address, Report Filed Date, Report Name, Amended`.
TEXP columns: same identity/report columns plus `Payee Type/Name/Address, Transaction Category (+ Others)` — and NO employer/occupation.

2026 TCON facts that shape the design: Transaction Types are `Contribution` (Itemized Monetary 97,303 / Non-Itemized Monetary 204,543 / Itemized Nonmoney 845), `Loan` (1,059), `Return Contribution` (443). Filer types: PAC 271,068 rows, **Candidate 31,482 rows across 921 distinct candidate filers**, County Party 1,566, Independent Expenditure Filer 74, Party 3. `Election Type` is populated per row (General 15,871 / Primary 16,563 / Primary Runoff 624 / General Runoff 80 / "No Election" 271,055 — the last is PAC-dominated). `Amended` = Y on 149 rows.

### Filer registration search (identity + server-computed totals)

`POST /api/PublicFilerDetails/GetCandidateCommitteDetails` body `{"pageNumber":N,"pageSize":N,"filerName":"<text>"}` — **the filter key is `filerName`**; `searchText`/`lastName`/`candidateName` are silently ignored (probe-confirmed: wrong keys return the full unfiltered set). Empty filter + pageSize 1000 pages the full registry (10,733 registrations at probe — a full-sweep artifact is 11 requests). Per row: **`filerEntityID`** (stable numeric, equals CSV `Filing Entity ID`), `guid` (per-cycle registration), `filerEntityVersionID`, `filerType`, `filerTypeCode` (`CAN`/`PAC`/`IEF`/`SFIFILER`/`LCF` local…), structured `firstName`/`lastName`/`suffix`, `committeeName`, `office`, `officeDistrictName`, `jurisdictionName`, `politicalParty`, `electionYear` (cycle), `filingYear`, `isPaperFiler`, and **`totalRaised` / `totalSpent` / `balanceofFunds` — server-computed, cycle-cumulative** (Sanders, Governor, entity 1004: $7,870,507.53 / $5,717,191.87).

### Transaction search (per-filer rows, numeric amounts)

`POST /api/PublicTransactionDetails/GetTransactionDetails` body `{"filerRegistrationGuid":"<guid>","transactionTypeCode":"TCON"|"TEXP","pageNumber":N,"pageSize":N}` — pageSize 1000 verified; registration-guid scoping verified (= built-in cycle scoping). 1,425,693 rows all-time. Rows carry numeric `transactionAmount`, `sourceName`, **`employerName`, `occupation`**, `transactionSource`, `reportName`, `transactionSubTypeDesc`, `transactionCategory`, `hasChild`, `guid`. **Thinner than NH's rows: NO `filerReportId`/`filerReportVersionId`/`isAmended`, no Transaction Type (loan vs contribution), no election type/year** — so NH's current-report-version selection (`newHampshirePhaseZero.ts`) does not port directly; AR amendment discrimination must come from the CSV `Amended` column + the filed-reports endpoint, per gate 4.

### Filed reports + per-filer secondary endpoints

`POST /api/PublicFiledReportAndDownload/GetPublicFilingReport` body `{"filerName":…,"pageNumber":…,"pageSize":…}` → per-report `reportVersion` ("Original"/…), `filerReportVersionId`, `reportStatus`, `filerReportGuid`, report **PDF path**, due/filed dates, `filerRegistrationGuid` (Sanders: 37 reports). This is the amendment-lineage source. Also verified: `PublicFilerDetails/GetCombinedFinancialTotalsDetails` (per-registration widget: interest/loan/monetary/expenditure cumulatives + endBalance — **CAUTION: for Sanders it returned numbers matching roughly one report period, not the cycle; semantics unpinned, do not use until gate 2 pins it**), `PublicLookup/GetOfficeSoughtLookup` (GET; 42 offices), `PublicFilerDetails/GetNextElectionYear`. `Lookup/ToGetFilingYears` is 401 for anonymous callers — enumerate export years empirically (2022 known floor; probe year+1 each cycle).

## Hard facts that shape the design

1. **Headline totals come from the registration row, not CSV sums.** Cent reconciliation on Sanders across all five filing-year CSVs: raised overshoots the server total by ~$31k ≈ her Itemized Nonmoney sum (so `totalRaised` appears monetary-only) with a $213.06 residual; spent falls short by **−$257,172.88** because **the TEXP CSV omits rows the search API has** (2,909 API expenditure rows vs 1,527 CSV rows for her registration; `hasChild` credit-card-style itemization is the suspect). Consequence: v1 publishes `total_raised`/`total_spent` from `GetCandidateCommitteDetails` rows and treats every CSV or API sum as a cross-check, not the headline. Gate 2 pins exactly what `totalRaised` includes — above all **whether loans are included** (the shared contract excludes loans from `total_raised`; Wilson-style filers with six-figure loans are the test case). If loans turn out to be included, raised must be published from reconciled receipt sums instead, and the gate documents that fork.
2. **Occupation is first-class and must be merged from two columns.** Individual-source rows in the 2026 TCON: 301,059; occupation filled 261,131 (87%) — but only ~50k on the `Occupation` dropdown column alone; the rest live in `Occupation Other` (free text, and dropdown values also appear wrapped as `Other(<text>)`). Merge rule: prefer `Occupation`, fall back to `Occupation Other`, unwrap the `Other(...)` wrapper, store both verbatim. The $200 aggregate statutory threshold does NOT mean small rows are blank: **99.7% of itemized individual rows ≤ $200 carry occupation** (73,278/73,475) — never filter occupation by transaction amount. `Retired`/`Self-Employed`/etc. stay honest categories; employer text is stored but not published (same as Missouri fact 1); no industry classification of direct-donor occupations.
3. **Candidate-specific outside spending is out of v1 — the absence is proven.** The IEF filer type exists (182 expenditure rows / 74 contribution rows in 2026, almost all NRA Political Victory Fund), but no structured stance or target candidate exists in the TEXP CSV, the transaction-search rows, or any mapped public endpoint; stance lives only in free text ("SMS MESSAGING IN SUPPORT OF BRANDON ACHOR, AR-SD-13"). The shared writer requires an explicit support/oppose pair — so AR v1 ships **direct-only, outside omitted entirely** (South Carolina precedent), not `$0`. No stance inference from descriptions, committee names, or payees, ever. Revisit only if the state adds a structured field; a curated description parse is a separate, human-reviewed follow-up at best (current volume doesn't justify it).
4. **Amendment semantics are unpinned and gate publication of any summed number.** The TCON CSV has an explicit `Amended` Y/N column (149/304k in 2026) and the filed-reports endpoint exposes full version lineage — but whether the CSV contains only-current rows (Amended flag = informational) or original+amended rows (naive sums double-count) is unknown. Gate 4 answers it with one amended filer: sum the filer's CSV rows with and without `Amended=Y`, compare to the registration-row total and to `GetPublicFilingReport` lineage. The cheapest correct outcome (CSV = current-only) needs no machinery; the other outcome requires report-name-keyed version selection before any CSV-derived number ships.
5. **Cycle scoping crosses filing years and uses the registration, not the calendar.** Sanders' 2026-cycle registration covers transactions from Nov 2022 through today, spread across all five filing-year CSVs. The registration `guid` scopes the search API for free; the CSVs scope only by `Filing Entity ID` + (`Election Year`/`Election Type`) columns. Gate 5 pins the CSV↔registration cycle join on a filer with more than one cycle (`filerEntityVersionID` > 1) before any CSV aggregation is trusted; until then, per-filer receipt work prefers the search API.
6. **Rows carry contributor street addresses.** Same PII rules as Missouri/NC: restricted artifact cache, never in product tables, never in logs, sanitized fixtures only.
7. **Coverage boundaries are explicit.** CFIS data floor = filing year 2022 (fine for Nov-2026); county/municipal filings are centrally filed only from the 2025 acts forward; school-board/township completeness is registration-verified but not filings-verified; the 2017–2023 predecessor era is currently unreachable. These become coverage notes where they bite, and `minElectionYear` keeps v1 out of the unproven history.

## Architecture

New module `backend/src/pipeline/arkansasFinance/`, tables `ar_candidate_finance_*` (five-table canonical shape, names well under 63 chars) via `createStandardStateFinanceSnapshotWriter` — config mirrors NH's writer (`newHampshireFinanceWriter.ts`): `manualLinkProtection: true`, `supersededLinkSource` set to the AR automatic link source, replace-merge, `minElectionYear: 2026` (widen later only behind gates 4/5). Link + outside identity = `filerEntityID` (stable numeric) / filer display name. Direct category types: **`["occupation", "contribution_size"]`** (NH used `industry` because its occupation column was empty; AR's is not — fact 2). No outside snapshot in v1 (fact 3).

File layout mirrors `newHampshireFinance/`:

```text
arkansasCfisClient.ts            # API base + endpoint map, bulk export streaming (sha256, chmod 0600), search + registration + filed-report calls, ENOTFOUND guidance (DNS defect)
arkansasCfisArtifactCache.ts     # NH cache pattern: per filing-year TCON/TEXP artifacts, hash + manifest + pinned parser version, restricted PII dir
arkansasCfisCsv.ts               # strict header pin (22-col TCON / 19-col TEXP), currency-cents parser, Amended flag
arkansasCandidateFilerResolver.ts # registration rows -> VoteApp candidates: exact office + district + jurisdiction + cycle + name evidence, fail closed
arkansasCandidateFinanceAutoLink.ts
arkansasCandidateFinanceSync.ts
arkansasDirectContributionAggregator.ts   # occupation + size buckets from receipts; merge rule per fact 2
arkansasFinanceEligibleOffices.ts # enumerated from GetOfficeSoughtLookup (42 offices), not guessed
arkansasFinanceWriter.ts
arkansasBallotLookupFinanceLoader.ts
arkansasPhaseZero.ts             # gate computations (reconciliation, amendment, cycle-join)
index.ts
```

Aggregation split (fact 1): headline `total_raised`/`total_spent` from the registration row; occupation and contribution-size breakdowns from receipt rows (search API per linked registration guid preferred; CSV allowed only after gates 4+5 pass). Non-itemized receipts stay in totals as unitemized money and out of the occupation chart; organization/PAC contributors stay in totals and size buckets and out of the occupation chart; loans and returns follow the shared contract (loans excluded from raised — enforced or forked per gate 2).

```sh
#!/bin/sh
# Promote the reviewed LOCAL Arkansas finance snapshot to prod (Connecticut recipe:
# TRUNCATE + pg_dump --data-only in ONE transaction). Usage:
#   sh ar-promote.sh dry  '<prod DSN with ?sslmode=require>'   # counts only
#   sh ar-promote.sh apply '<prod DSN with ?sslmode=require>'
set -eu
MODE=${1:?dry|apply}; PROD=${2:?prod DSN}
LOCAL=postgresql://localhost:5432/voteapp
DUMP=$(dirname "$0")/ar_finance_local.sql
TABLES="ar_candidate_finance_links ar_candidate_finance_summaries ar_candidate_finance_direct_breakdowns ar_candidate_finance_outside_groups ar_candidate_finance_outside_group_breakdowns"
COUNTS="select 'links', count(*) from ar_candidate_finance_links union all select 'summaries', count(*) from ar_candidate_finance_summaries union all select 'breakdowns', count(*) from ar_candidate_finance_direct_breakdowns union all select 'raised', sum(total_receipts)::bigint from ar_candidate_finance_summaries"
echo "== local"; psql "$LOCAL" -Atc "$COUNTS"
echo "== prod before"; psql "$PROD" -Atc "$COUNTS"
# Prod must already have the 5 tables (migration 266); the links' FKs to candidates/elections make the restore fail if prod lacks a row.
psql "$PROD" -Atc "select count(*) from schema_migrations where filename like '266_%'" | grep -q 1 || { echo "migration 266 missing on prod"; exit 1; }
T=""; for t in $TABLES; do T="$T -t public.$t"; done
pg_dump "$LOCAL" --data-only --no-owner --no-privileges $T > "$DUMP"
{
  echo "BEGIN;"
  echo "TRUNCATE $(echo $TABLES | sed 's/ /, /g');"
  cat "$DUMP"
  if [ "$MODE" = apply ]; then echo "COMMIT;"; else echo "ROLLBACK;"; fi
} > "$DUMP.txn"
psql "$PROD" -v ON_ERROR_STOP=1 -q -f "$DUMP.txn"
echo "== prod after ($MODE)"; psql "$PROD" -Atc "$COUNTS"
```
